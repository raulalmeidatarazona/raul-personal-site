Estrategia 1: Ejecución Selectiva de Pruebas 🔢 (Test Impact Analysis)

¿Qué es?

El Test Impact Analysis (TIA) identifica qué pruebas son relevantes para los cambios recientes en el código, reduciendo significativamente el tiempo de prueba.

¿Cómo Funciona?

  1. Cobertura de Código: Identifica qué partes del código afectan cada prueba.

  2. Histórico de Cambios: Analiza cómo las modificaciones anteriores han impactado las pruebas.

  3. Dependencias entre Módulos: Evalúa cómo las dependencias afectan la ejecución de pruebas.

Ejemplo con Jest (JavaScript):

// tests/component.test.js

test('Header component renders correctly', () => {
  const { getByText } = render(<Header title="Dashboard" />);
  expect(getByText('Dashboard')).toBeInTheDocument();
});

// Run only affected tests

// Command: jest --findRelatedTests src/component/Header.js

Beneficios:

  • Reducción de tiempo: Al ejecutar solo las pruebas relevantes, se disminuye el tiempo total de prueba.

  • Eficiencia: Mejora la eficiencia del flujo de trabajo al centrarse en áreas del código que han cambiado.

Estrategia 2: Paralelización de Pruebas 💡

¿Por qué Paralelizar?

Ejecutar pruebas en paralelo distribuye la carga de trabajo entre múltiples núcleos de CPU, acelerando el proceso de validación.

Técnicas Clave:

🔹 División por tipo de prueba: Unitarias, integración, E2E.

🔹 Balanceo de carga entre workers.

🔹 Priorización de pruebas lentas.

Implementación con Pytest (Python):

# pyproject.toml

[tool.pytest.ini_options]
addopts = "-n auto --dist=loadscope"
testpaths = ["tests"]
# Ejecución optimizada

pytest --cache-clear --junitxml=results.xml

Beneficios:

  • Aceleración: Reducción significativa del tiempo de ejecución de pruebas en proyectos grandes (dora.dev).

  • Escalabilidad: Mejora en la gestión de suites de pruebas extensas.

Estrategia 3: Cacheo de Dependencias 🔄

¿Qué es?

El cacheo de dependencias evita la descarga e instalación repetitiva de librerías cada vez que se ejecuta la suite de pruebas.

Ejemplo Práctico con Docker:

# Dockerfile.ci
FROM node:18

# Cache dependencies
COPY package*.json .
RUN npm ci --prefer-offline

# Copy only necessary files
COPY src/ src/
COPY tests/ tests/

Beneficios:

🔹 92% menos tiempo en la instalación de dependencias.

🔹 Elimina redundancia en CI/CD.

Estrategia 4: Análisis Incremental de Calidad 📈

¿Cómo Funciona?

Analiza y valida solo los archivos modificados en lugar de todo el código.

Script Unificado (Bash):

#!/bin/bash

# Get modified files

CHANGED=$(git diff --cached --name-only --diff-filter=ACM)

# Lint only changed JavaScript files

echo "$CHANGED" | grep '.js$' | xargs eslint --cache --max-warnings 0

# Type checking for TypeScript

echo "$CHANGED" | grep '.tsx?$' | xargs tsc --noEmit

# Security audit for dependencies

echo "$CHANGED" | grep 'package.json' && npm audit --production

Beneficios:

  • Rapidez: Validación más rápida al centrarse solo en los cambios recientes.

  • Prevención: Detección temprana de posibles problemas en el código modificado.

Estrategia 5: Timeouts Dinámicos ⏱

¿Por qué Importan?

Ajustar los timeouts según el entorno de ejecución puede prevenir bloqueos innecesarios y mejorar la eficiencia.

Lógica Adaptativa:

# hooks/timeout_manager.py

import os
from datetime import datetime

def calculate_timeout():
    test_env = os.getenv('TEST_ENV', 'local')
    base_time = 30  # segundos

    multipliers = {
        'ci': 1.5,
        'local': 1.0,
        'debug': 3.0
    }

    # Reduce timeout after business hours

    hour = datetime.now().hour
    if 18 < hour < 8:
        return base_time * 0.7

    return base_time * multipliers.get(test_env, 1.0)

Implementación Final: Hook Pre-Push Optimizado 🚀

#!/usr/bin/env bash

# ---- Configuration ----

MAX_TEST_TIME=300  # 5 minutes
PARALLEL_WORKERS=80%
BRANCH_WHITELIST="main develop staging"

# ---- Branch Check ----

current_branch=$(git rev-parse --abbrev-ref HEAD)

if [[ ! "$BRANCH_WHITELIST" =~ $current_branch ]]; then
  echo "[SKIP] Pre-push disabled for branch: $current_branch"
  exit 0
fi

# ---- Changed Files ----

modified_files=$(git diff --cached --name-only --diff-filter=ACM)

# ---- Security Check ----

echo "$modified_files" | grep 'package.json' && \
  npm audit --production --audit-level=moderate

# ---- Smart Testing ----

start_time=$(date +%s)

# JavaScript/TypeScript projects

if echo "$modified_files" | grep -qE '\.(js|ts)x?$'; then
  jest --findRelatedTests $modified_files \
       --maxWorkers=$PARALLEL_WORKERS \
       --testTimeout=$(calculate_timeout) \
       --ci
fi

# Python projects

if echo "$modified_files" | grep -qE '\.py$'; then
  pytest --cov --cov-report=term \
         -n auto \
         --durations=10 \
         --timeout=120 \
         --tb=short \
         -m "not slow"
fi

# ---- Time Budget Check ----

elapsed=$(( $(date +%s) - start_time ))

if [ $elapsed -gt $MAX_TEST_TIME ]; then
  echo "⚠️  Tests exceeded time budget: ${elapsed}s > ${MAX_TEST_TIME}s"
  exit 1
fi

exit 0
